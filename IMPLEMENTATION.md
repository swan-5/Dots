## 2. Screens implemented (S00–S08)

All nine screens in the PRD are implemented and wired into navigation:

- **S00 Onboarding** — 3-page swipeable intro, Skip/Next, optional "record first Dot"
  or "later", never forces data entry. No account/sign-in.
- **S01 Timeline** — search + category chips (All/Life/Career/Both), year/month
  grouped list, newest/oldest toggle, floating `+`, empty state.
- **S02 New/Edit Dot** — title + date required, everything else optional (category,
  body, tags, location, URL, one photo via `PhotosPicker`), delete with impact warning.
- **S03 Dot Detail** — full content, "Connected to" list (from `Connection`s),
  "Connect another Dot" → routes to Universe with this Dot preselected.
- **S04 Universe** — dark canvas, "My Constellations" previews + "Unconnected Dots"
  grid, `Connect Dots` / `Create Constellation` entry points.
- **S05 Create/Edit Constellation** — title, template picker (5 templates), live
  preview via the cardinality-aware mapper, 2+ Dot multi-select.
- **S06 Constellation Detail** — header (custom title + real constellation name),
  canvas with tap-to-open stars, chronological member list, edit/delete, "create a
  Story from this constellation."
- **S07 My Story** — list, create/edit (title, Personal/Career, ordered Dot picker,
  own prose), detail with ordered list + plain-text `ShareLink`.
- **S08 Profile** — appearance (System/Dark/Light), JSON export/import backup,
  delete-all-data, About (with constellation data attribution).

## 3. Key design decisions / invariants

- **Chronology is sorted, not stored.** `Dot` has no "display order" field — every
  list calls `ChronologySort.sorted(...)`, with a deterministic tiebreak
  (`eventDate` → `createdAt` → `id` string), so editing a date instantly re-sorts
  and ties never jump around.
- **Constellation cardinality policy** (`ConstellationMapper`): N == anchors → exact
  fill; N < anchors → fill the N *most prominent* anchors in chronological order,
  rest shown as dim "in progress" placeholders; N > anchors → fill all anchors,
  overflow goes to a clearly separate, chronologically-ordered list. Never silently
  drops or overlaps a Dot. Fully deterministic (same input → same mapping every time).
- **No dangling references on delete.** `DeletionService` scans and strips the
  deleted Dot's id from every `Connection`, `Constellation.memberDotIDs`,
  `Story.orderedDotIDs`, and `Reflection` before deleting it, and the delete
  confirmation UI shows the user what will be affected first.
- **Connection ≠ Constellation.** A `Connection` is a reasoned, dated link between
  exactly two Dots; a `Constellation` is a named group with no implied pairwise
  causality. Creating a constellation never creates `Connection` records.
- **Local-first, no account.** No login anywhere; SwiftData store is on-device only;
  Profile's export/import is explicitly the only way data moves between devices,
  and the UI says so.

## 4. Astronomy data note (read before relying on this for anything real)

The five bundled templates' star positions and line segments in
`ConstellationCatalog.swift` are **manually curated, shape-accurate
approximations**, laid out by hand to match each constellation's well-known
asterism (Orion's belt-and-shoulders, Cassiopeia's W, Lyra's parallelogram,
Cygnus' Northern Cross, Ursa Major's Big Dipper). They were authored from general
astronomical knowledge, not pulled from a live star catalog (this environment has
no network access at build time) and are **not arc-second-precise**. Per the PRD's
own guardrail ("ship fewer templates rather than fake astronomical accuracy"),
only these 5 are included, and `About` in Profile states the attribution/caveat
plainly rather than implying survey-grade precision.

## 5. Known limitations

- **Astronomy data precision** — see §4.
- **No app icon** — `ASSETCATALOG_COMPILER_APPICON_NAME` is intentionally unset so
  the project builds without one; add a real icon before shipping.
- **Single photo per Dot** — PRD allowed starting with one image; multi-photo is a
  P1 item, not built.
- **Backup conflict strategy is "existing wins"** — importing a JSON backup skips
  any record whose id already exists locally; it never overwrites. No merge UI.
- **Reflection model has no UI** — the SwiftData entity exists (future-ready, per
  PRD S03) but nothing creates or displays a `Reflection` yet.
- **Story export is plain text only** — PDF/AI drafting is explicitly out of scope
  per the PRD.
- **No photo compression/resizing** — a picked photo is stored as-is
  (`.externalStorage` attribute keeps it out of the main SQLite file, but large
  originals will still use real disk space).
- **Onboarding page-indicator dots** may be visually covered by the Skip/Next
  control row at the bottom on some screen sizes — cosmetic, not functional.
- **Manual, on-device simulator interaction in this environment was unreliable** —
  the automated tap/swipe tool used during development queued/delayed input
  unpredictably (a known environment quirk, not an app bug). Build succeeded,
  the unit test suite passed (see §7), and onboarding, the Universe tab, and the
  Constellation-creation sheet were each visually confirmed via screenshot, but a
  full manual walkthrough of every flow (creating a Dot, connecting two Dots,
  building a full constellation, writing a Story, export/import) still needs a
  human pass in Simulator or on a device before shipping.

## 6. How to run

```bash
cd /Users/swan/dots
xcodegen generate        # regenerate Dots.xcodeproj after any project.yml change
open Dots.xcodeproj
```

Run the `Dots` scheme on an iOS 17+ simulator or device. Or from the command line:

```bash
xcodebuild -project Dots.xcodeproj -scheme Dots \
  -destination 'platform=iOS Simulator,name=<some installed simulator>' build
```

## 7. Tests — actual results

Ran on 2026-10-18 against an iPhone 17 Pro Max simulator (iOS 26.5):

```
xcodebuild -project Dots.xcodeproj -scheme Dots \
  -destination 'id=<simulator-udid>' test
```

**14/14 tests passed, 0 failures:**

- `ChronologyTests` (4) — chronology independent of creation order; same-date
  tiebreak is deterministic regardless of input order; editing a date re-sorts
  correctly; month grouping is correct and order-preserving.
- `ConstellationMappingTests` (5) — exact fill has no placeholders/overflow; fewer
  dots than anchors fills the most prominent anchors first and marks partial;
  more dots than anchors fills all anchors and puts the rest in overflow with
  nothing dropped; mapping is deterministic across repeated/shuffled calls; all 5
  catalog templates have internally-consistent line/anchor references.
- `DeletionIntegrityTests` (5) — deleting a Dot removes its Connections; removes it
  from Constellation membership without deleting the Constellation; removes it
  from Story membership; duplicate-connection detection is symmetric and
  kind-aware; impact summary reports every affected record correctly.

## 8. Manual test instructions

1. **First launch**: confirm onboarding's 3 pages, Skip and "나중에 할게요" both
   land on Timeline with an empty state.
2. **Acceptance criterion #1**: create a Dot (title + date only), force-quit,
   relaunch, confirm it's still there.
3. **Acceptance criterion #2**: create Dots dated 2023, 2025, 2024 in that
   creation order; confirm Timeline shows 2023 → 2024 → 2025 (oldest-first toggle)
   regardless of creation order.
4. **Acceptance criterion #3**: edit a Dot's date; confirm Timeline re-sorts
   immediately and any existing Connection's `discoveredAt` is untouched.
5. Create 2+ Dots, go to Universe → **Connect Dots**, pick source/destination,
   required reason, confirm it saves and appears in both Dots' "연결된 경험".
6. Universe → **Create Constellation**, pick a template and 2+ Dots, confirm the
   preview mapping and the save; open the saved constellation, tap a star, confirm
   it opens the correct Dot with its real date.
7. Delete a Dot that's in a Connection + Constellation + Story; confirm the warning
   names all three, and after deleting, none of them contain a dangling reference.
8. My Story: create a story from 3+ Dots, reorder them, confirm Share → plain text
   output lists them in the chosen order.
9. Profile: export JSON, delete all data, import the same file back, confirm
   counts match and nothing duplicates on a second import.
10. Settings/Accessibility: toggle Dark/Light/System, enable Reduce Motion in
    Simulator's Accessibility settings, confirm constellation canvas skips the
    appear animation; enable VoiceOver and confirm each star and timeline row has
    a sensible spoken label.
